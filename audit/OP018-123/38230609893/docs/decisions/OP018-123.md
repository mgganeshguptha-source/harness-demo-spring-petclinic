# Decisions — OP018-123

Source: stories/OP018-123.md @ 392c5dfabd5f

## D-OP018-123-1: Vet specialty access never returns null

- Question: Can `getSpecialtiesInternal()` return `null`?
- Answer: `getSpecialtiesInternal()` never returns `null`; it creates an empty set if needed.
- Applies to: `org.springframework.samples.petclinic.vet.Vet#getSpecialtiesInternal()`, `Vet.specialties`
- Scope: service

## D-OP018-123-2: Vet specialties remain eagerly loaded

- Question: Are there lazy-loading or transaction concerns when reading a vet's specialties?
- Answer: `specialties` are mapped `FetchType.EAGER`, so they are always loaded with the `Vet`; methods that read specialties must not add transactional handling or change the mapping.
- Applies to: `org.springframework.samples.petclinic.vet.Vet.specialties`, specialty-reading logic on `Vet`
- Scope: service

## D-OP018-123-3: Vet specialty name checks trim outer whitespace

- Question: How should leading and trailing whitespace around a non-blank specialty name be handled?
- Answer: Trim the input name before comparison, compare it case-insensitively with each stored specialty name without modifying the stored names, keep internal whitespace unchanged, and return `false` when the trimmed name is blank.
- Applies to: `org.springframework.samples.petclinic.vet.Vet.hasSpecialty(String)`
- Scope: service
