Title: Add a method to find a Vet's specialty by name

Story: As a developer, I want to get a Vet's Specialty object by its name, so calling code can use the specialty (for example its id) directly instead of looping over the specialty list.

Expected behaviour: Vet gains public Optional<Specialty> findSpecialty(String name). It returns the vet's specialty whose name matches the given name, compared case-insensitively ("Surgery" finds "surgery"). It returns Optional.empty() when no specialty matches, when the vet has no specialties, or when name is null or blank. It reads the existing specialties through getSpecialtiesInternal() and does not change how specialties are stored or added.

Acceptance criteria:

Vet with specialty "surgery": findSpecialty("surgery") and findSpecialty("Surgery") both return that Specialty.
Vet with specialty "surgery": findSpecialty("dentistry") returns Optional.empty().
Vet with no specialties: findSpecialty("surgery") returns Optional.empty().
findSpecialty(null) and findSpecialty(" ") return Optional.empty() and do not throw.
findSpecialty does not add, remove or modify specialties. Existing behaviour (getSpecialties, getNrOfSpecialties, hasSpecialty, addSpecialty) is unchanged.
findSpecialty(name).isPresent() equals hasSpecialty(name) for every name.

In scope: the Vet class only. Out of scope: UI, templates, controllers, repositories, database.
